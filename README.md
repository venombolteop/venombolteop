<details>
<summary><b>⚙️ Profile Automation — how everything stays live</b></summary>

This profile uses GitHub Actions to refresh generated visualisations and repository traffic data:

| Workflow | What it does | Runs |
|---|---|---|
| [`visitor-counter.yml`](.github/workflows/visitor-counter.yml) | Pulls this repository's GitHub traffic data and updates the cumulative repository-view counter | Every 6 hours + manual |
| [`profile-3d.yml`](.github/workflows/profile-3d.yml) | Renders the **3D contribution graph** with the [yoshi389111/github-profile-3d-contrib](https://github.com/yoshi389111/github-profile-3d-contrib) action | Every day + manual |
| [`metrics.yml`](.github/workflows/metrics.yml) | Generates the **rich metrics card** (private + public contributions, languages, achievements, lines of code) with [lowlighter/metrics](https://github.com/lowlighter/metrics) — aggregates only, **never shows repo names** (the upstream achievements plugin is disabled until its retired Projects API query is fixed) | Every day + manual |
| [`snake.yml`](.github/workflows/snake.yml) | Regenerates the animated **contribution snake** and pushes it to the `output` branch | Every 6 hours + manual |

**The profile-view badge** is provided by [visitor-badge.laobi.icu](https://visitor-badge.laobi.icu). Like other external counters, its result can be affected by caching and image requests.

**The animated graphics** (banner, terminal, skill bars, wave divider) are custom SVG files in the [`assets/`](assets/) folder of this repo — fully self-hosted, so they never break and no third party is involved.

> 💡 The 3D graph image appears after the `Generate 3D Contribution Graph` workflow has run once — trigger it manually from the **Actions** tab, or wait for the daily schedule.

<details>
<summary><b>🔐 Want private contributions in the metrics card? (one-time setup)</b></summary>

The default `GITHUB_TOKEN` can only see **public** data. To include your **private** contributions (still no repo names or details — just numbers):

1. Go to **github.com → Settings → Developer settings → Personal access tokens → Tokens (classic)**
2. **Generate new token (classic)** → tick the `repo` scope → **Generate** → copy the token
3. Back on this repo: **Settings → Secrets and variables → Actions → New repository secret**
   - **Name:** `METRICS_TOKEN`
   - **Value:** paste the token
4. Run the **GitHub Metrics** workflow from the **Actions** tab once

The token is stored encrypted by GitHub and never appears in the README. If you skip this step, the metrics card simply renders with public data only.

> 🔒 Tip: the classic `repo`-scoped token is the standard for this. For maximum paranoia, use a **fine-grained** token limited to read access on your private repos and store it the same way.
